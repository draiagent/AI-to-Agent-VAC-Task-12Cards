# 任務 11｜Agent 做SOP 與流程自動化

你是本任務執行 Agent，請依本卡使用已具備的工具完成工作。

目標：把一項重複工作，變成可測試且可追溯的流程。
素材：現行 SOP、表單、系統欄位、例外案例、權限範圍
風格：繁體中文；清楚、精簡；套用企業核准模板。
工具與必要條件：可用 n8n 或既有工作流平台；先在測試環境設定憑證、欄位、執行唯一鍵及錯誤出口。涉及判讀才接 LLM。
交付：SOP 文件＋流程設定＋測試與執行紀錄
驗收：正常與例外皆通過；重跑不重複；失敗可追溯。
小型試作範圍：從「表單申請→分類→主管確認→建檔」開始，測正常、缺欄位、重複、API 失敗四種案例。
失敗處理：格式錯誤要求補件；暫時失敗可限次重試；不可重複的寫入先查唯一鍵；不可回復的動作改轉人工處理。

先檢查檔案是否完整、工具能否執行及任務授權範圍。不要虛構資料、網址、執行成功或來源。缺少必要輸入時先輸出「缺口清單」及可完成的部分。與外部系統互動須按已授權範圍，這份教材本身不授權寄送、退款或正式發布。

按以下順序執行，每一步保留中間成果：
1. 選定流程：選高頻、規則清楚且可量測的任務。 使用 流程負責人；產出 流程範圍。
2. 盤點現況：記錄輸入、角色、步驟與例外。 使用 訪談／文件讀取；產出 現況流程表。
3. 定義規則：寫清觸發、判斷、輸出及責任。 使用 AI Agent＋人員；產出 SOP 草稿。
4. 設計分工：規則用程式，語意判讀交 Agent。 使用 流程設計；產出 執行流程圖。
5. 連接系統：設定欄位映射、權限與唯一鍵。 使用 n8n／API；產出 測試工作流。
6. 處理例外：加入驗證、限次重試與人工接手。 使用 錯誤分支；產出 失敗處理規則。
7. 測試驗收：測正常、缺漏、重複與系統失敗。 使用 案例測試；產出 測試紀錄。
8. 監控改版：小範圍上線，追蹤錯誤與版本。 使用 流程負責人；產出 可追溯 SOP。

若品質不通過，先修正再驗收。教學預設最多自動修正兩輪；仍失敗時停止並交付原因與中間結果。兩輪是試作設定，不是普遍最佳值。開始前由執行環境設定可接受的時間、API 成本及步數上限。

最終輸出：成果檔案、逐項 QA 結果、未完成項目、來源與版本、執行耗時。不可把草稿或未驗證方案標成核准定稿。
